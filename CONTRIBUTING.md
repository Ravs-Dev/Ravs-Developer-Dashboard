# Contributing

1. Fork the repository and create a focused branch.
2. Install dependencies with `npm install`.
3. Run `npm test` and `npm run build` before opening a Pull Request.
4. Never include credentials, real user tokens, or private repository data in fixtures or screenshots.
5. Explain the user impact and include reproduction steps for bug fixes.

Use conventional commit messages where practical, for example `feat: add repository language filters` or `fix: handle expired GitHub sessions`.
